# Проверка главного меню HP2/M212

Это приватная тестовая сборка для двух ПК с собственными копиями HP2/M212.
`Play-Menu-Test.cmd` показывает стартовый экран с исходным фоном и кнопками
игры. На нём есть «Новая игра», «Загрузка игры», «Настройка», «Кооператив» и
«Версус». В каждом сетевом режиме есть «Создать сервер» и «Подключиться».
Исходный встроенный Windows-фронтенд Game.exe остаётся доступен для загрузки
сохранений и настройки; его три кнопки физически не изменены.
Меню рассчитано на двух игроков. Co-op кампания пока экспериментальная и не
прошла приёмку полного прохождения или проверку на двух физических ПК.

## Подготовка

На каждом ПК распакуйте **один и тот же** тестовый комплект в отдельный каталог,
откройте PowerShell в нём и укажите путь к своей установленной игре. Команды
работают с отдельной копией; установленную игру и её сохранения не меняют.

```powershell
$gameRoot = 'D:\Games\HP2-M212' # замените своим путём
$workRoot = Join-Path (Get-Location) '.local\game'
.\scripts\Prepare-LocalGame.ps1 -GameRoot $gameRoot -WorkRoot $workRoot
$runtime = '.local\distribution\hp2-runtime-20260920-163839-818-d45d6265.json'
$artifact = '.local\distribution\hp2-test-build-20260921-003721-386-d3cfc7e9.zip'
.\scripts\Test-RuntimeCompatibility.ps1 -WorkRoot $workRoot -Manifest $runtime
.\scripts\Import-TestBuild.ps1 -WorkRoot $workRoot -Artifact $artifact -ValidateOnly
.\scripts\Import-TestBuild.ps1 -WorkRoot $workRoot -Artifact $artifact
```

Продолжайте, только если совместимость вернула `COMPATIBLE`, а проверка архива —
`VALIDATED`. При импорте Game.exe и UCC.exe рабочей копии должны быть закрыты.
Оба ПК должны получить один и тот же архив: независимая компиляция может создать
несовместимые сетевые package GUID. SHA-256 архива:
`0f60edff4c472aacafc16491856712fc923c49b028df19789cc993258571c5c7`.

## Запуск через меню

На ПК A запустите [Play-Menu-Test.cmd](../Play-Menu-Test.cmd) двойным щелчком
из распакованного комплекта либо выполните в PowerShell:

```powershell
.\scripts\Show-MenuTest.ps1
```

Экран использует изображения из локальной установленной игры и не требует
дополнительного игрового архива. «Новая игра» открывает `PrivetDr.unr` с
обычным `Engine.GameInfo`. «Загрузка игры» и «Настройка» открывают исходное
меню, где нужно выбрать соответствующий пункт ещё раз. Каждый запуск Game.exe
создаёт лог с уникальным именем и отдельный тестовый профиль.

Для сети на ПК A выберите «Кооператив» либо «Версус» → «Создать сервер».
Сервер использует порт 7777, вмещает двух игроков и сразу
запускает соответствующую карту. Если Windows спросит доступ к сети, разрешите
игре работу в вашей локальной сети. Узнайте IPv4 адрес ПК A через `ipconfig`.

На ПК B запустите то же меню, выберите **тот же режим**, нажмите «Подключиться»,
укажите IPv4 адрес ПК A, порт `7777` и своё имя. Поле адреса и порта влияет
только на подключение; хост использует 7777. Для проверки на одном ПК можно
ввести `127.0.0.1`. Выбор неверного режима должен быть отвергнут сервером.

В Versus движение — WASD/стрелки, Space — прыжок, 1–6 — выбор заклинания,
левая кнопка мыши — выстрел. Одиночные настройки клавиш при переходе в Versus
не переписываются. Co-op использует исходное наведение и заклинания кампании.

После проверки пришлите три session-лога: сервер и клиент для сетевого запуска,
а также отдельный лог одиночного запуска; укажите, что фактически было видно
на экранах и работали ли управление/камеры. Логи запуска через скрипт имеют
имя `HP2MP-menu-*.log` и лежат в `Документы\HP2-Multiplayer-Development`.
Особенно полезны строки `InitGame`, `[MP_LOGIN]`, `Join succeeded`,
`[MP_CUTSCENE]` и `HPVersusSpellSelect`. Переходы кнопок стартового экрана
проверены автоматически, а страницы осмотрены в отрисованном превью. Локальный
сетевой smoke test подтвердил загрузку карт и вход двух игроков, но изображение
и управление на двух физических ПК ещё требуют вашей проверки.
