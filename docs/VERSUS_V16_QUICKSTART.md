# Versus v16: сборка и проверка на двух ПК

Если вам передали готовый приватный `hp2-versus-friend-*.zip`, распакуйте его
в короткий путь (`C:\HP2MP`) и выполните
`.\scripts\Setup-VersusTestKit.ps1 -GameRoot 'ПУТЬ_К_ИГРЕ'`. Затем запустите
`Play-Menu-Test.cmd`. Этот путь устанавливает **тот же** проверенный бинарный
комплект и тестовую карту; Python и локальная перекомпиляция не нужны.

В репозитории находятся только исходные модификации. На каждом Windows-ПК нужны
собственная установленная HP2/M212 и локальный архив
`HPVersus_v16_remote_bottom_align_20260905.zip` с SHA-256
`A2B13B924BF9BBA9F81C6A70E38024657C71F6F1F861FA49BF3F812C86EFB9BF`.
Оригинальные файлы игры в Git не публикуются.

Проект можно получить через `git clone` либо кнопкой GitHub **Download ZIP**.
Выбирайте ветку `codex/versus-8-spawn-map`: ZIP ветки `main` не содержит
текущий Versus. HUD принят в `9dbd9c4` и последующие исправления не меняют
его внешний вид. Масштабы взрослых персонажей уточняются отдельно.
Распакуйте ZIP в короткий путь, например `C:\HP2MP`: старый M212 UCC
падал до компиляции при вложенном `System` длиной 111 символов, тогда как
тот же архив в более коротком пути собрался.
Git для сборки не обязателен: в ZIP-копии нет служебной папки `.git`, поэтому
поля commit/branch в журнале сборки останутся пустыми. Это штатный режим и на
пакеты игры не влияет.

Установите настоящий Python **3.9 или новее** (например, с python.org с опцией
`Add python.exe to PATH`) и откройте новый PowerShell. Store alias в
`WindowsApps` сборкой не принимается. Положите указанный v16-архив в корень
распакованного репозитория. Для Versus выполните из этого корня две команды:

```powershell
.\scripts\Prepare-VersusV16.ps1 -GameRoot 'ПУТЬ_К_ИГРЕ'
.\Build.ps1 -VersusV16
```

Для игры на двух ПК используйте **одну и ту же собранную пару** `HGame.u` и
`M212Share.u`: повторная компиляция одинаковых исходников может создать другие
GUID пакетов. Хост экспортирует проверенный комплект командой
`.\scripts\Export-TestBuild.ps1 -WorkRoot .local\versus-v16-game` и передаёт
выведенный приватный ZIP другу. На втором ПК после подготовки WorkRoot:

```powershell
.\scripts\Import-TestBuild.ps1 -WorkRoot .local\versus-v16-game -Artifact 'ПУТЬ_К_ПОЛУЧЕННОМУ_ZIP' -ValidateOnly
.\scripts\Import-TestBuild.ps1 -WorkRoot .local\versus-v16-game -Artifact 'ПУТЬ_К_ПОЛУЧЕННОМУ_ZIP'
```

Импорт сверяет оба пакета и обновляет запись PASS, которую читает меню Versus.
Не добавляйте игровые пакеты в публичный Git. После импорта на втором ПК не
запускайте `Build.ps1` до сетевого теста.

Если `.local\versus-v16-game` уже существует и его состояние неизвестно,
сохраните его и задайте **один и тот же новый** `-WorkRoot` обеим командам,
например `.local\versus-v16-clean-2`. Сборка выводит фактический SHA-256
несовпавшего исходника и сохраняет Python traceback в `.local\builds`.
Сборка в отдельном `-WorkRoot` больше не переключает запись PASS для
`Play-Menu-Test.cmd`: её собственный результат хранится внутри этого WorkRoot.
Проверенная цепочка трёх ключевых классов описана в
[аудите сборки](audits/VERSUS_V16_BUILD_CHAIN_20260927.md).

Подготовьте **копию** `Startup.unr` в `.local\versus-v16-game\Maps` по
[инструкции импорта шести стартов](STARTUP_VERSUS_SPAWNS.md). Убедитесь, что
на карте восемь `HPVersusStart` с индексами 0–7. На этом ПК карта уже
подготовлена; оригинал игры не менялся. Повторный импорт создаст дубликаты.

Запуск: `Play-Menu-Test.cmd` → «Версус». Выберите Гарри, Рона или Гермиону.
Создатель сервера задаёт 2–8 мест и число фрагов, затем нажимает «Запустить
сервер». Меню поднимает отдельный UCC-сервер на порту 7777 и подключает
локальный клиент. Второй ПК выбирает «Подключиться», вводит IPv4-адрес
создателя и порт 7777. Имя и персонаж сохраняются только в локальном меню.
Закрытие окна создателя завершает его сервер. Управление: WASD/стрелки,
Space, левая кнопка мыши — Риктусемпра, F3 — таблица до восьми игроков.
Поля X/Y и ширины/высоты задают начальный прямоугольник каждого окна; после
старта стандартную рамку можно перетаскивать и растягивать мышью.

Что подтверждено локально:

| Проверка | Результат |
| --- | --- |
| Чистая сборка v16 и отдельная сборка co-op | 0 ошибок у обеих |
| Меню: dedicated Startup, локальный вход, имя/персонаж/лимиты | Серверный журнал подтвердил |
| Два клиента, выбор Рона и Гермионы; два Рона | Сервер принял все варианты, Native-движение согласовано |
| Риктусемпра: снаряд → попадание → HP → смерть/фраг/победитель | Прошло с одноразовой серверной диагностикой и реальными подключёнными клиентами; нажатие у клиента этим не проверялось |
| Три игрока: каждый атакует обоих остальных | Шесть серверных снарядов попали во всех трёх; HP каждого снизилось со 100 до 70. Клиентский ввод не проверялся |
| Восемь клиентов, девятый, выход/возврат | Восемь разных слотов, девятому отказ, освободившийся слот занят снова |
| Восемь участников: массовый залп, три смерти и респауна | Сервер создал восемь снарядов, все восемь попали; три игрока независимо возродились с HP 100, личные фраги/смерти верны. Стрельба инициирована временной серверной диагностикой |
| Отсчёт, победа, повторный матч | Прошло в серверной диагностике двух игроков |
| Два видимых окна, свободное перемещение/масштабирование рамки, модели Рона/Гермионы и полный player-набор анимаций | Нативная рамка и изменение размера проверены локально; пользователь подтвердил прыжок/стрейф/отход назад. Для плащей добавлены отдельные каналы родных male/female анимаций; требуется финальный визуальный просмотр |
| HUD в viewport: HP `current / 100`, иконка/название заклинания, READY/COOLDOWN | Визуально принят пользователем на `9dbd9c4`; дальнейшие сборки не меняют его исходник |
| Массовый бой руками восьми игроков и два физических ПК | **Не проверено** |

Журналы конкретных сессий остаются в `.local\runs`, результаты сборок — в
`.local\builds`. При тесте на двух ПК запишите, видно ли обе модели, работают ли
камера, движение, F3, Риктусемпра и респаун. Это ещё необходимо для игровой
приёмки, несмотря на успешные серверные проверки.
